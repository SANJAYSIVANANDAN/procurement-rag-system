# ADR-026: The Streamlit UI: decisions made while building M16

**Status:** Accepted (V1)

The pages, the state and the rules (the UI never touches PostgreSQL, Redis or RabbitMQ and holds no business logic) come from the spec (§27). These are the decisions the spec left open.

- **The UI cannot import the backend, and the build checks it.** Two import contracts: `frontend` may not import `covenantiq`, and `covenantiq` may not import `frontend`. The UI's own copy of the API's shapes is plain dictionaries read from the JSON, so a change to the API shows up as a failing UI test, not as a shared type that hides it.
- **Pages are plain functions, and logic is in modules that do not import Streamlit.** `api_client.py` (HTTP), `sse.py` (following a reply and folding events) and `presenters.py` (wording, grouping, exports, the comparison matrix) are tested without a browser. A page does layout and calls those. Colours and labels live in `presenters.py` only.
- **Answers are drawn twice on purpose.** The streamed draft is shown while the model writes, and replaced by the validated final text when `message_complete` arrives (the server may have removed markers or appended a notice). A reply that arrives without a terminal event after three reconnects ends with a retryable `STREAM_LOST` error and the partial text greyed out.
- **Text from documents and models is escaped before it is marked up.** Markers like `[C1]` become small badges linked to the citation entry; everything else is HTML-escaped first, so a contract cannot inject markup into the page.
- **Reconnect rules live in one place.** `stream_events` retries a dropped stream up to three times with `Last-Event-ID` (waiting 0.5 s, 1 s, 1.5 s). An error the API itself reports (a 404 or 401) is raised at once, since reconnecting cannot help.
- **A 401 anywhere returns to login.** Every call goes through `state.call`, which clears the session and leaves a notice. Other errors are shown with their reference id.
- **The dashboard is computed in the UI because the API has no dashboard endpoint.** It totals documents, vendors, findings (of up to 30 ready documents) and the latest assessment of up to 20 vendors, cached for 30 seconds. "Recent activity" is the latest document updates: there is no endpoint listing jobs. If these grow, a summary endpoint belongs in the API, not more calls here.
- **"Why this answer?" is built from what the stream reported** (the stages, the number of cited passages and documents, the grounding result, the output tokens). The API does not expose the retrieval trace of a message, so the page cannot show retrieval scores or the evidence decision.
- **Comparison never charts what cannot be compared.** Not-comparable cells are shaded and say so, with the reason underneath; the chart and the leader come only from dimensions the API marked comparable. A suppressed ranking is shown with the API's reason.
- **Sign-in is per browser session.** The token lives in `st.session_state` only, so a refresh signs the user out (spec 27.3: "the token is re-entered (V1)"); history and scope reload from the API after signing in again.
- **Not done:** a sign-in that survives a refresh (needs a cookie component and a decision about token storage), per-user theming, and a language other than English.
