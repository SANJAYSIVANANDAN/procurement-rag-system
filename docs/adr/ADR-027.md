# ADR-027: Two safeguards found by the integration tests (M17)

**Status:** Accepted (V1)

M17 added tests for the spec's critical cases (`docs/test-matrix.md`). Two of them failed on first run and led to code changes.

- **Tracebacks no longer print local variables.** structlog's JSON traceback renderer and its console (rich) renderer both include the values of local variables by default. A logged exception in a chat reply, an ingestion task or the login code could therefore write contract text, a question, a prompt or a password into the logs. Both renderers are now configured with `show_locals=False`; the stack, the exception type and its message are unchanged. `unit/core/test_logging.py` and `integration/chat/test_chat_flows.py` check both formats. Exception *messages* are still logged, so code must keep putting no document text in them.
- **A per-reply canary in the answer prompt.** Prompt injection defence was: documents are flagged by a scanner, wrapped and escaped as data, and the system prompt says never to follow them. The citation check does not help against a model that obeys anyway: it only tests markers, numbers and quotes, so any sentence carrying a valid `[C1]` is accepted whatever it says. The spec's test list names a canary for this. Each answer request now carries a fresh random reference, "never write it in an answer"; a draft that contains it is replaced by a short refusal (`grounding_status = abstained`, `chat.canary_leaked` logged, trace `validation.canary_leaked = 1`). Limits: the tokens are streamed before validation, so a listener may briefly see the leaked text until `message_complete` replaces it; the canary catches leaking the instructions, not an injected claim the passage itself states.
- **Foreign ids in a conversation's scope are dropped without an error** (existing behaviour, now covered by a test). Answering 404 or 422 would let a user probe which document ids exist; dropping them reveals nothing and attaches nothing. The ownership matrix checks that the conversation's `documents` stays empty.
