# ADR-019 — Retrieval engine: decisions made while building M9

**Status:** Accepted (V1)

The shape of the engine is fixed by the spec (§19): dense and lexical search, reciprocal rank fusion, optional reranking, parent expansion, an evidence gate and a deterministic citation validator. These are the decisions the spec left open, and where the implementation goes beyond it.

- **The engine is a library with ports.** `rag/` imports no `api` or `services` code. It reaches the database through a factory of read-only sessions (`search_session_factory`), gets an embedding provider and an optional reranker injected, and a cache that fails open. The chat graph, contract analysis and vendor assessment (later milestones) all call `RetrievalEngine.retrieve`.
- **Every search filters in SQL, not only in the caller.** Owner, the allowed document ids, and the document being `ready` and not deleted are in every query (dense, lexical, hydration, parents, neighbours). A caller that wrongly names another user's document, or a stale id of a deleted one, gets nothing back. This is tested, including with the caller deliberately passing both users' document ids.
- **Dense search is exact for small sets.** Below `CIQ_EXACT_SCAN_THRESHOLD` chunks (5,000), `SET LOCAL enable_indexscan = off` makes the scan exact; above it the HNSW index is used with `hnsw.ef_search = 100` and, on pgvector 0.8 or later, `hnsw.iterative_scan = relaxed_order` so tight filters do not cost recall. The `SET LOCAL` settings end with the transaction (tested).
- **Chunks embedded with another model are never searched.** Vectors from different models are not comparable, so dense search filters on `embedding_model`. When none match, the trace says so and names `covenantiq reembed`; keyword search still answers meanwhile.
- **The embedding provider being down degrades, it does not fail.** The query cannot be embedded, so dense search is skipped and the trace says so; the lexical half still returns results.
- **Reranking is optional at every level** (switched off, no reranker, a timeout, an error, a partial answer): the fused order is kept, `trace.rerank_skipped` records why, and the evidence gate then uses the stricter rank-agreement rule and never returns `strong` (§19.8, 19.10). Rerank scores are cached per `(model, query, chunk)` for an hour and only the uncached candidates are sent to the reranker.
- **Caches cannot slow a request down.** Each lookup has a 250 ms timeout, any failure reads as a miss, three failures in a row skip the cache for 30 seconds, and all 30 rerank scores are fetched with one `MGET`. This was found by trying the CLI against an unreachable Redis: it took 16 seconds before and 0.9 seconds after. Cache keys contain a hash of the query, never the text.
- **Keywords are rule-based.** Stop words and generic legal filler (`shall`, `may`, `agreement`, `clause`) are dropped because they match every line; legal references (`6.2`, `Schedule 3`, `non-renewal`) are kept; quoted phrases stay phrases. The result is a `websearch_to_tsquery` string passed as a bound parameter, and tests feed it SQL-injection and operator strings.
- **Context is built so a document cannot break out of its block.** A literal `<source` or `</source` in document text, and any quote or angle bracket in a document title, is escaped. Flagged chunks (injection score 0.5 or more) get `warning="possible embedded instructions"`. A group that does not fit the token budget is dropped whole, along with everything ranked below it.
- **Citation validation goes slightly beyond the spec in three ways**, all of them making it stricter:
  1. A quoted span must match the source; if any quotation in a sentence is fabricated, the sentence is unsupported whatever else matches (the spec's "or" would let a fabricated quote pass on word overlap).
  2. A digit in a cited sentence must appear in its source ("60 days" cited to a source that says 90 fails even at 90% word overlap).
  3. A marker placed after the full stop (`... 90 days. [C2]`) is attributed to the sentence before it.
  A sentence with no content words that can be checked (`Yes [C1].`) counts as unsupported.
- **Stemming is Snowball (English), fuzzy matching is `rapidfuzz`**, as the spec names. Snowball is imperfect (`liable` and `liability` do not share a stem); the keyword-coverage and overlap thresholds are initial values to calibrate against the evaluation set (milestone 14).
- **Scores depend on the reranker.** The evidence thresholds in `config/rag.yaml` (0.55, 0.35, 0.70) assume scores in [0, 1] that mean the same thing across queries. Cohere v5 scores are calibrated; the local Ettin model's squashed logits and the toy lexical reranker are not. They need their own values before the gate is relied on.
- **Not built:** the Voyage reranker adapter (Cohere and the local Ettin model replace it, ADR-017 and ADR-018), query classification and rewriting by the LLM (milestone 11), and any retrieval cache for results (the spec excludes it).
