# ADR-018 — Cohere as the hosted reranker

**Status:** Accepted (V1, optional provider)

- **Decision:** `CIQ_RERANK_PROVIDER=cohere` reranks with Cohere's hosted API (`POST https://api.cohere.com/v2/rerank`). The default model is `rerank-v5.0-fast`, built for low latency, which the 3 second reranking budget (spec 19.8) needs; `CIQ_RERANK_MODEL=rerank-v5.0-pro` is the highest-quality option (both have a 32k-token context and support 100+ languages). The key is read from `COHERE_API_KEY` (also `CIQ_COHERE_API_KEY` or `CO_API_KEY`) and is never logged or included in an error.
- **Why Cohere over the local Ettin model (ADR-017):** reranking runs on Cohere's hardware, so 30 candidates fit the 3 second budget that a CPU cannot meet (about 12 s for the Ettin 150M model with 8 CPUs). Cohere's v5 models return calibrated scores in [0, 1], so the spec's evidence thresholds (0.55 / 0.35 / 0.30, section 19.10) are plausible as written; the Ettin model's raw, unbounded scores are squashed with a sigmoid and would need recalibration. The Ettin reranker stays available for deployments that cannot send contract text outside the network.
- **Consequences:**
  - **Contract text leaves the deployment.** Every reranked passage (the query and up to 30 chunks of about 350 tokens) is sent to Cohere. The deployment notes must say so (spec section 4.7), as they already do for the LLM and the embedding provider.
  - **Failure handling is the same as for the other reranker.** Any failure (timeout, 429, 5xx, a rejected key) makes the caller keep the fused order; after three in a row the client skips the call for 30 seconds. A bad key is counted too, so it cannot make every query call out. Bad requests (400, 404, 422) are rejections and do not open the breaker.
  - **Nothing identifying is sent**: no `X-Client-Name`, no document ids; passages are cut to 1,024 tokens each (`max_tokens_per_doc`), which bounds the billed size.
  - **Cost and limits:** billed per search unit (one query with up to 100 documents); trial keys are rate limited. Not measured here: no key was available.
  - The adapter uses `httpx` against the REST API instead of Cohere's SDK, like the OpenAI-compatible embedding adapter: one fewer dependency, and the request is fully visible in tests. The spec prefers vendor SDKs where they exist; this is a deliberate deviation.
