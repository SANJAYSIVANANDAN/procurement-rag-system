# ADR-012 — Hosted embeddings and reranking, with offline fakes for CI

**Status:** Accepted (V1)

- **Decision:** Defaults are Voyage `voyage-law-2` (1024-d) and Voyage rerank. CI and offline development use deterministic fakes (`CIQ_EMBEDDING_PROVIDER=fake`, `CIQ_RERANK_PROVIDER=fake`).
- **Consequences:** Ingestion needs network access and an API key. The embedding task is rate-limited and retries on 429. `document_chunks.embedding_model` records which model produced each vector, and changing the model requires a re-embed job (§18.8).

## Addendum (M8): how embeddings are used

- **Document vs query input.** Voyage models take an `input_type`. Passages are embedded as `document` and search queries as `query`; the provider interface has separate `embed_documents` and `embed_query` methods so a caller cannot mix them up.
- **Context header.** A passage is embedded with its place in front of it: `{title} | {heading path} | clause {ref}`. The header is stored in `metadata.heading_text` (and weighted A in the full-text index) but is not part of the stored `text`, so citations quote the contract exactly.
- **One model per database.** `voyage-law-2` returns 1024 dimensions only, which is the width of `document_chunks.embedding`. Settings validation rejects a known model whose dimension differs. An OpenAI-compatible endpoint is allowed for air-gapped installs, but its dimension must also be 1024; a different width needs a migration.
- **Failures.** A provider that is down or throttling is retried with exponential backoff inside the call, and again by the task (the job is released to `queued` before each retry, so the retried delivery can claim it). A bad API key fails the job at once (`EMBEDDING_AUTH_FAILED`). A rejected input is isolated by halving the batch; a passage the provider refuses is recorded in its metadata and skipped, and the document is `ready` if at most 2 percent of its passages were refused, otherwise the job fails with `EMBEDDING_FAILED`.
- **Resumable.** Each batch is committed as soon as it is embedded. A retry sends only the passages without a vector.
- **Changing model.** `covenantiq reembed` clears the vectors of ready or failed documents and queues the embedding stage again, without extracting or chunking anything. Set `CIQ_EMBEDDING_MODEL` first.
- **OpenAI as the embedding provider.** `CIQ_EMBEDDING_PROVIDER=openai_compat` with `CIQ_EMBEDDING_MODEL=text-embedding-3-small` and `CIQ_OPENAI_COMPAT_BASE_URL=https://api.openai.com/v1` works through the OpenAI-compatible adapter (`OPENAI_API_KEY` is accepted as well as `CIQ_OPENAI_COMPAT_API_KEY`). The model returns 1536 dimensions natively; the adapter asks for `dimensions=1024` so the vectors fit the 1024-wide column (the `text-embedding-3` models are trained so a shortened vector stays useful, and OpenAI renormalises it). Queries and documents are both sent with the same `dimensions`. Settings validation refuses a dimension above the model's native size. OpenAI does not distinguish query from document input, so retrieval quality for legal text should be measured (M9 onward) before treating it as equal to `voyage-law-2`. Reranking is a separate setting (`CIQ_RERANK_PROVIDER`, default Voyage); set it to `none` when no Voyage key is available. Contract text is sent to OpenAI when this provider is used.
- **Checking a configuration.** `covenantiq check-embeddings` embeds three short generic sentences with the configured provider and reports model, dimension and a related-versus-unrelated similarity check, without printing keys.
